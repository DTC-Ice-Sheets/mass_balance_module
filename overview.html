Overview

The Mass Balance Module estimates the mass balance of the Greenland Ice Sheet (a future update will include Antarctica) from Earth Observation (EO) data. It is one of the ice-sheet process modules of the ESA Digital Twin Component for Ice Sheets (DTC Ice Sheets, DTC-IS), developed under the ESA Digital Twin Earth (DTE) programme.

The module converts satellite radar-altimetry surface elevation change, together with other EO-derived features such as ice velocity and land surface temperature, into gridded mass balance estimates in gigatonnes per year (Gt yr-1). In a wider DTC-IS context, this module feeds the Use Case 2: EU Sea-Level Response Fingerprint. There, its output drives the Sea-Level Response EMulator (SELREM), which converts ice-sheet mass change into global and regional sea-level fingerprints, with a focus on European coastlines.

The module also supports what-if scenarios: users can perturb the input forcings (for example scaling ice velocity or applying a temperature offset) and see how the predicted mass balance, and in turn the sea-level response, changes.

Scientific background

The module follows the calibrated radar-altimetry method of Simonsen et al. (2021), which produced a Greenland Ice Sheet mass balance record for 1992–2020. Combining several EO datasets with machine learning makes this a hybrid mass balance estimate.

Surface elevation change from radar altimetry. The module builds on the long record of Ku-band radar altimetry over the Greenland Ice Sheet. This record was first developed in the ESA Climate Change Initiative (CCI) and is now produced operationally by the Copernicus Climate Change Service (C3S). The standard C3S product gives monthly surface elevation change (SEC) on a 25 km grid, from ERS-1, ERS-2, ENVISAT, CryoSat-2 and Sentinel-3A/B (Sørensen et al., 2018). For DTC-IS, DTU runs a modified version of the C3S processing that shortens the CryoSat-2 and Sentinel-3 data window from 3 to 2 years and refines the grid from 25 km to 5 km. This higher-resolution SEC record is hosted on the DTC-IS EO data store and updated as new data become available.

From volume change to mass change. Radar altimetry measures changes in surface height, that is volume change. To convert it to mass change you need to know how firn compaction, radar penetration and changes in acquisition mode affect the measured signal. Following Simonsen et al. (2021), the method learns time-varying calibration fields that convert radar-derived elevation change into ice-equivalent (mass) elevation change. The original model was trained to reproduce the ICESat-derived mass balance (Sørensen et al., 2011) from a set of a priori features. Ten candidate features were tested in 768 combinations. The preferred model was chosen for its agreement with independent IMBIE and GRACE mass balance, its consistency with the static ICESat (2003–2009) calibration field, and the glaciological plausibility of its spatial patterns in the 1990s.

Machine-learning model. The method was originally built on an AdaBoost decision-tree ensemble. The operational implementation in this package uses a pre-trained XGBoost (gradient-boosted decision tree) model. The model is downloaded at run time and its SHA-256 checksum is checked before it is loaded. It predicts the rate of ice-equivalent elevation change (m ice eq. yr-1) for each grid cell from:

  • the observed annual radar elevation change (RAdh),

  • radar-altimetry acquisition features from the C3S radar-altimetry product: the acquisition mode (RAmode, LRM vs. SARIn, with CryoSat-2 SARIn starting over Greenland in October 2010) and the distance from the nearest satellite observation to the grid point (RAdist),

  • ice surface velocity (iv),

  • land surface temperature (LST),

  • location (grid X/Y in EPSG:3413, NSIDC Polar Stereographic North).

The prediction provides mass balance in Gt yr-1. Only the pre-trained model runs inside the digital twin. All input features are retrieved from the DTC-IS EO data store through the Data Download Module (DDM) for the time period the user selects.

Module workflow

The package exposes five command-line entry points that are chained together in the DTC-IS workflow. See Quick Start for example commands and API Reference for the full API.

Entry point

Purpose

mass_balance_enhance_elevation_data_entrypoint

Converts a cumulative, irregularly sampled elevation-change cube into annual (calendar-year) elevation change and rescales windows that are not exactly one year long. The radar-altimetry features (RAdh, RAdist, RAmode) in the feature dataset are then replaced with these updated annual values.

mass_balance_enhance_temperature_data_entrypoint

Replaces the land surface temperature feature with a new temperature dataset (for example the C3S land surface temperature, or projections from the ECMWF Climate Change Adaptation Digital Twin), aggregated to annual means and interpolated onto the model grid.

mass_balance_prediction_entrypoint

Applies the user-defined what-if perturbations, runs the XGBoost model and derives gridded mass balance (Gt yr-1). The grid can optionally be downsampled first.

mass_balance_postprocessing_entrypoint

Compares a predicted mass balance run with a control run and writes totals, grid metadata, input features and the prediction to JSON for the DTC-IS dashboard.

mass_balance_from_thickness_entrypoint

Converts modelled ice thickness, for example ISMIP6 ice-sheet model projections, into gridded mass balance. By default it also reshapes the result into the point time series expected by SELREM, so modelled future mass change can be used alongside the EO-based estimate.

A typical observation-driven run is:

  1. Retrieve the feature dataset (GeoZarr) and, optionally, updated elevation change and temperature data through the DDM.

  2. Enhance the feature dataset with the updated elevation and/or temperature data.

  3. Predict the mass balance, once as a control (no perturbation) and once with the user’s what-if settings.

  4. Post-process the results for display, and/or pass the mass balance to SELREM to compute the sea-level response.

What-if scenarios

DTC-IS lets users explore how the ice sheet would respond to changed forcing, not just reproduce observations. The prediction entry point applies the following perturbations to the input features before the model runs:

Option

Default

Effect

--ice_velocity_factor

1.0

Multiplies the ice velocity feature (iv).

--land_surface_temperature_offset

0.0

Adds an offset to the land surface temperature feature (LST).

--radar_elevation_factor

1.0

Multiplies the observed radar elevation change feature (RAdh).

The temperature enhancement step also lets you replace observed surface temperature with projected temperature fields. The C3S land surface temperature record and runs driven by the ECMWF Climate Change Adaptation Digital Twin have been used this way to make short-term mass balance forecasts. Running the post-processing step on a control run and a perturbed run gives the change in total mass balance caused by the scenario. Passing the result to SELREM shows how that change affects regional sea level.

Validation and uncertainty

The module has been validated for the Greenland Ice Sheet. The radar-altimetry volume mass balance (radar-VMB) estimate was compared with the following independent datasets:

  • satellite gravimetry from GRACE/GRACE-FO (Barletta et al., 2020),

  • input–output (mass budget) estimates by Mouginot et al. (2019), Colgan et al. (2019) and Mankoff et al. (2021), and

  • the IMBIE reconciled assessment (Otosaka et al., 2023).

Over the 28-year record (1992–2020), the radar-VMB reproduces both the long-term trend and the interannual variability of Greenland mass balance within the uncertainties of these independent estimates. It is strongly correlated with the GRACE mass balance in both timing and size of the fluctuations. Compared year by year with the mass budget record of Mankoff et al. (2021), the root-mean-square error (RMSE) is 86 Gt yr-1.

The largest discrepancies occur in years of unusually low mass loss (1992, 1995–1998 and 2019), when the model underestimates how much mass the ice sheet retained. This is a known limitation of decision-tree ensembles. They do not capture extreme or non-linear events at the edge of the training data well, such as the cooling after the 1991 Pinatubo eruption. The model can also misinterpret climate extremes, so its results for such years should be interpreted with care.

The independent validation datasets do not always agree with each other within their stated uncertainties (2014, for example). The module therefore reports RMSE against reference datasets as a quantitative measure of performance. Because the model is fast, many feature-perturbation experiments (more than 1000) can be run alongside the mass balance calculation and used to propagate errors from start to finish through the mass balance and SELREM chain. The Antarctic Ice Sheet will be validated against an Antarctic mass balance assessment once the Antarctic model is released.

Limitations and ongoing development

  • Spatial coverage. The module currently covers the Greenland Ice Sheet only, on the EPSG:3413 grid. The method can be transferred to Antarctica using the Antarctic C3S elevation-change and ice-velocity products. This extension is ongoing and is considered incremental research with low risk.

  • Extreme years. Like other decision-tree ensembles, the model cannot extrapolate far outside the conditions it was trained on (see Validation and uncertainty). Results for anomalous years and for strongly perturbed what-if scenarios should be read with this in mind.

  • Future projections. Future mass change from ice-sheet model projections (ISMIP6; Nowicki et al., 2016) can be brought into the same framework through the thickness-to-mass-balance entry point. R&D continues on how best to combine these projections with the EO-driven estimate, so that user-defined what-if scenarios stay within the range of modelled futures.

  • Towards hybrid, explainable models. A purely data-driven model offers limited insight into physical processes. In the future, the module could possibly move towards hybrid, explainable models that combine EO data with physical constraints on ice and snow processes. Approaches of interest include symbolic regression (e.g. Qlattice; Wilstrup and Kasak, 2021) and physics-informed neural networks such as PINNICLE (Cheng et al., 2024).

Related DTC-IS components

  • Sea-Level Response EMulator (SELREM), in the sea_level_response package: turns mass balance from this module (or from user-supplied or ISMIP6 datasets) into global and local sea-level fingerprints with uncertainties.

  • Data Download Module (DDM): retrieves the EO input features from the DTC-IS EO data store and other sources.

  • DTC-IS Query API and dashboards: run the module as part of the Use Case 2 workflow. Users can choose a time range and what-if parameters in the interactive dashboard or the accompanying Jupyter Notebook, and export intermediate mass balance datasets.

How to cite

If you use mass balance estimates produced by this module, please cite the underlying method:

Simonsen, S. B., Barletta, V. R., Colgan, W. T., & Sørensen, L. S. (2021). Greenland Ice Sheet mass balance (1992–2020) from calibrated radar altimetry. Geophysical Research Letters, 48, e2020GL091216. https://doi.org/10.1029/2020GL091216

and mention that the estimates were produced with the DTC Ice Sheets Mass Balance Module [date].
